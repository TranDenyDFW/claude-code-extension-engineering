# Composition cards

> Claude Code 2.1.220, verified 2026-07-29. Delta from 2.1.219: none (changelog: bug fixes and reliability improvements only).


One row per mechanism pairing, compressed to a single line so a combination can be checked without opening both references first. Owner, failure path and regression test stay as a terse per-pairing checklist rather than expanded prose, because baseline testing showed a model generates that guidance unaided; the reason this file exists at all is the part it cannot generate, which is the version gates and config filenames.


| Pairing | Card |
|---|---|
| Skill + Hook | trigger = the lifecycle event the hook matches; instruction owner = SKILL.md; executor = the model, after the hook admits the action; enforcement point = hook exit code; external dependency = none; package boundary = both ship in one plugin or neither; version gate = the hook event must exist in the target Claude Code version; failure path = decide explicitly whether the hook fails open or closed; regression test = the event firing with and without the Skill installed. |
| Skill + Subagent | trigger = the caller delegating; instruction owner = SKILL.md preloaded into the agent; executor = a named subagent; enforcement point = none, this pairing is advisory; external dependency = none; package boundary = the agent definition and the Skill ship together; version gate = named subagents need no version gate on current builds; failure path = the agent returns nothing or a partial result; regression test = the same task inline versus delegated. |
| Skill + Slash invocation | trigger = an explicit /name, or a description match; instruction owner = SKILL.md; executor = the model in the current session; enforcement point = none, this is discovery not enforcement; external dependency = none; package boundary = one Skill directory; version gate = custom commands merged into Skills, so a legacy flat command file is the old shape; failure path = the Skill never fires and nobody notices, because explicit invocation still works; regression test = both entry paths produce the same result. |
| Skill + Hook + Subagent | trigger = the lifecycle event; instruction owner = SKILL.md; executor = the subagent; enforcement point = hook exit code; external dependency = none; package boundary = one plugin; version gate = the hook event plus named-subagent support; failure path = the hook decides whether a dead agent blocks or proceeds; regression test = each pair, then all three together. |
| Hook dispatching model logic | trigger = the lifecycle event; instruction owner = the hook's prompt or agent definition; executor = a model, not a script; enforcement point = the hook's exit code, derived from a model verdict; external dependency = model availability and latency; package boundary = one plugin; version gate = the prompt and agent handler types, with agent marked experimental in current docs; failure path = the model is unavailable or returns an unparseable verdict, which must be an explicit decision rather than a default; regression test = repeat-run one input and measure verdict stability. |
| Skill instructing when to delegate | trigger = a Skill description match in the main session; instruction owner = SKILL.md holds the routing rule, the agent definition holds the task contract; executor = the named subagent; enforcement point = none, the model may ignore the routing advice; external dependency = none; package boundary = the Skill and the agent definitions ship together or routing points at nothing; version gate = named subagents need no version gate on current builds; failure path = routed to the wrong agent, or to none, with a plausible answer either way; regression test = in-scope and out-of-scope prompts, asserting the agent identity. |
| Plugin bundling Skill + Hook + Agent | trigger = install and enable; instruction owner = each component; executor = per component, the model for the Skill, the handler for the hook, the subagent for the agent; enforcement point = the bundled hook only; external dependency = the marketplace or repository; package boundary = the plugin is the boundary, and components must sit at the plugin root rather than inside the manifest directory; version gate = ZIP loading at 2.1.128 and claude plugin init at 2.1.157; failure path = the manifest is rejected and every component fails together; regression test = claude plugin validate, then a clean-profile install exercising all three. |
| CLAUDE.md + Skill | trigger = every session for CLAUDE.md, description match for the Skill; instruction owner = split, and duplicating the rule across both is the common defect; executor = the model; enforcement point = none, both are advisory; external dependency = none; package boundary = CLAUDE.md is project-local while the Skill is packageable; version gate = auto memory available by 2.1.59; failure path = the model follows one and ignores the other; regression test = remove each in turn and observe what changes. |
| Skill + MCP | trigger = Skill description match; instruction owner = SKILL.md; executor = the model calling MCP tools; enforcement point = the MCP permission prompt; external dependency = the server and its credentials; package boundary = a plugin may bundle the server definition but never its secrets; version gate = MCP trust behavior changed at 2.1.196 and tightened at 2.1.207; failure path = server down, expired auth, or schema drift; regression test = healthy, unreachable, and error-payload runs. |
| Hook + MCP | trigger = the lifecycle event; instruction owner = the hook handler; executor = the hook process or an mcp_tool handler; enforcement point = hook exit code; external dependency = the MCP server; package boundary = one plugin; version gate = the mcp_tool handler type and the Elicitation events; failure path = timeout, where the fail-open or fail-closed choice must be explicit; regression test = server healthy, slow, and down. |
| Agent Team + MCP | trigger = team task assignment; instruction owner = the team task plus each agent definition; executor = independent Claude Code sessions; enforcement point = none at the team layer; external dependency = one MCP connection per teammate, so cost multiplies with team size; package boundary = team configuration is session-scoped; version gate = Agent Teams is experimental; the implicit lifecycle requires v2.1.178+; failure path = a teammate stalls while holding an assigned task; regression test = revoke a server mid-run. |
| Plugin bundle | trigger = install and enable; instruction owner = each bundled component; executor = whatever the component defines; enforcement point = bundled hooks only; external dependency = the marketplace or source repository; package boundary = this pairing is the boundary; version gate = ZIP loading at 2.1.128 and claude plugin init at 2.1.157; failure path = the manifest is rejected and nothing loads; regression test = claude plugin validate, then a clean-profile install. |
| Plugin + LSP | trigger = opening a file the server claims; instruction owner = .lsp.json; executor = the language server process; enforcement point = none; external dependency = the server binary and its runtime; package boundary = the plugin ships configuration and rarely the binary itself; version gate = the core LSP tool arrived at 2.0.74; failure path = binary not found, handshake failure, or the server dying mid-session; regression test = present, absent, and wrong-version binaries. |
| Workflow + Subagent | trigger = /name invocation or a caller running the script; instruction owner = the workflow script owns control flow, each agent() prompt owns its task; executor = subagents spawned by the runtime, capped at 16 concurrent and 1000 per run; enforcement point = the script itself, since loops and conditionals are code the model cannot reinterpret; external dependency = none; package boundary = one .claude/workflows/ file, or a plugin workflows/ component; version gate = stable since 2.1.154; failure path = a failed agent() resolves to null rather than throwing, so an unfiltered result array poisons downstream stages; regression test = one deliberately failing agent, asserting the script filters the null and completes. |
| Workflow + MCP | trigger = the script's agents calling MCP tools mid-run; instruction owner = the script for orchestration, the server schema for each call; executor = subagents reaching session-connected MCP servers through tool search; enforcement point = the MCP permission prompt per server; external dependency = the server, multiplied by fan-out, so a rate-limited server throttles the whole run; package boundary = the workflow ships without the server, and the pairing breaks where the server is absent, notably headless and cron contexts that skip interactively-authenticated servers; version gate = workflows at 2.1.154 plus the server's own trust behavior at 2.1.196+; failure path = an agent's MCP call times out and that item silently returns null; regression test = server healthy, then revoked mid-run. |
| Workflow + Plugin | trigger = install and enable, then /plugin:name; instruction owner = the bundled script; executor = the workflow runtime; enforcement point = the script; external dependency = the marketplace or repository; package boundary = a workflows/ directory at the plugin root, or the workflows manifest field, and a custom path field REPLACES the default folder rather than adding to it; version gate = workflows at 2.1.154, ZIP loading at 2.1.128; failure path = the namespaced /plugin:name collides with nothing but the un-namespaced local file wins in the same directory; regression test = clean-profile install, then invoke by the namespaced name. |
| Workflow + Hook | trigger = the lifecycle event fires the hook, whose handler launches the workflow; instruction owner = the hook wiring for WHEN, the script for WHAT; executor = the hook process, then the workflow runtime; enforcement point = the hook exit code gates whether the workflow runs at all; external dependency = none; package boundary = both ship in one plugin or the pairing dangles; version gate = the hook event must exist on the target build, workflows at 2.1.154; failure path = the hook fires but the workflow errors, and the event has already passed, so decide whether that fails open or closed BEFORE wiring it; regression test = event fires with the workflow present, absent, and erroring. |
| Skill + Subagent vs Workflow + Subagent vs Agent Team | the three ways to delegate, and the axis is WHO owns the control flow. Skill + Subagent: the MODEL owns it, advisory routing, cheapest, correct for one bounded job whose result returns to the caller. Workflow + Subagent: the SCRIPT owns it, deterministic loops and fan-out, 16 concurrent and 1000 per run, no filesystem API inside the script and no Date.now(), correct when the orchestration itself must not drift; stable since 2.1.154. Agent Team: NO ONE owns it centrally, peers message each other, experimental and env-gated behind CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS, one team per session with no nesting, cost multiplies per teammate, correct only when peers must challenge each other's findings mid-flight. Failure paths differ the same way: a mis-routed skill produces a plausible wrong answer, a workflow null-fills the failed item, a team stalls holding a task. Regression test = the same fan-out task through all three, asserting the workflow alone gives identical run-to-run structure. |
