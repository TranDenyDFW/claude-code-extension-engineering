Two page titles have drifted upstream without the URL changing: the memory page and the hooks guide. Three findings from verification:

- The hooks reference now says over-cap hook output is saved to a file and replaced with a preview, where this reference had said truncated; hooks.md was corrected the same day.
- SRC_ERRORS is `verified-partial`, the only row that is. The Error reference is long enough that two separate fetches on 2026-08-05 returned its early message-index rows but not its tail, so its late-page content is NOT confirmed live and nothing in this ledger depends on that fetch for it. Recording the partial rather than rounding it up to `verified` is the point: a status column that only ever says `verified` measures nothing.
- SRC_DISCOVER_PLUGINS was not planned. It was added because one claim in monitors.md (the append-after-the-conversation prompt-cache model) traces to that page and to no other mirrored page, and attributing it to a neighbouring plugins page would have been a wrong-but-plausible id that every gate in this repo would have passed.
- Keep a CONTENT-HASH LOCKFILE over mirrored external content, so drift lands in its own pull request rather than riding along invisibly inside an unrelated change. This is the mechanism that catches a corpus growing underneath a measurement, which is a failure this project has hit  [ENGINEERING]
- Carry a FREEZE FLAG so a sync cannot clobber local hardening applied on top of vendored content. Without one, the next sync silently reverts the fix and the revert looks like an upstream update  [ENGINEERING]
