## A. Explicitly requested, not delivered

These two were asked for directly and are the real gaps, not housekeeping.

### A1. Replicates 2 and 3 of the combine test

**Asked:** "DO A MORE COMPREHENSIVE COMBINE TEST - THE BIGGER THE BETTER - WE WANT TO
CONFIRM THAT COMBINING THEM HAS SOME SORT OF BENEFIT."

**Delivered:** one replicate. 60 scenarios, 4 arms, 240 sheets, 1,680 double-graded cells,
3,369 grade records. Result: D versus B is 20 wins, 20 losses, p=1.000, NEGATIVE.

**Why it still matters.** The published result is a NULL. The single largest unmeasured
source of variance in it is answer-agent nondeterminism, which only replication can see. A
null that holds across three independent answer passes is a materially stronger claim than a
null from one. This is the difference between "we did not detect a benefit" and "we looked
three times and it is not there."

**Already built and paid for, so the marginal cost is only the run:** the pooled endpoint
(`pooledPerScenarioDeltas`, `pooledVerdict`, `REPLICATE_RULE` in `tools/tier3-score.mjs`),
the repaired v2 keys, the 20-page docs mirror, the staging trees, and the two workflow
scripts.

**Cost:** ~48 answer agents (2 replicates x 4 arms x 6 batches) plus ~24 graders plus
adjudicators. This is what exhausted the session limit last time; budget a full window.

**Known work still needed before running:**
- `tier3-pack.mjs` needs a `--rep N` flag that suffixes outputs (`packets-v2-r2/`,
  `blinding-map-v2-r2.json`) AND salts `permutationFor` with the replicate number so sheet
  order differs across replicates. Not written.
- `tier3-score.mjs` needs a `--replicates` mode that loads the three (grades, map) pairs and
  calls `pooledVerdict`. The functions exist; the CLI path does not.

**Staging that already exists (may be stale, re-verify):**
`...\scratchpad\t3full-v2\` with `a/ b/ bplus/ d/` arm trees, docs mirror staged per arm,
and empty `answers-r2/ answers-r3/` directories.

**Check whether still real:**
```
ls <scratchpad>\t3full-v2\answers-r2    # empty at snapshot
grep -n "rep" <WORK>\tools\tier3-pack.mjs | grep -i "salt\|--rep"   # absent at snapshot
grep -n "replicates" <WORK>\tools\tier3-score.mjs                    # functions only, no CLI
```

**Honest caveat on expected value.** Replication tightens the confidence in the null; it is
unlikely to reverse it. D and B differ by 1 point with 20 ties out of 60. If the goal is
"confirm combining helps", replication is the rigorous way to close the question, not a
likely route to a positive.

## B. Known defects, disclosed but unfixed

### B1. S040 carries a bad key that costs every arm equally

The key's `primary` is an advisory remedy (restate the rule at each delegation) while the
SAME key's `failure_mode` concedes that "a hard guarantee needs a different mechanism
entirely, such as a permissions deny rule, a PreToolUse hook, or denying Agent(Explore)".
All four arms independently chose the deny rule, so all four score 0 on `primary` and on the
fields derived from it: roughly 20 zero-scores from one arguable key.

Does NOT bias D against B (hits all arms identically), but depresses every absolute number.
Disclosed in the v2 limitations.

**Fix:** repair the key under the same blind, quote-verified discipline, then re-score. Note
that changing a key after seeing results needs care: do it blind to arm outcomes, log it in
`key-repairs-v2.md`, and re-run the scorer rather than hand-editing any table.

### B2. keys-lint cannot catch the S040 defect class

Missing rule: **the key's own `failure_mode` (or `rejection_reason`) names a mechanism that
would better satisfy the scenario than the key's `primary`.** This is the highest-value lint
addition outstanding, because it catches keys that argue against themselves, which is exactly
the S040 shape and adjacent to the already-caught version_caveat self-contradiction.

Likely heuristic: tag mechanisms in `primary` and in `failure_mode`/`rejection_reason` with
the existing `mechanismTag()`; WARN when the latter names a harness-owned mechanism while
`primary` is model-owned advisory. Start as WARN, not ERROR.

**Check:** `grep -n "failure_mode" <WORK>\tools\tier3-keys-lint.mjs` (no such rule at
snapshot).

### B3. Arm A identifies itself in 10 of its 60 sheets

Phrases like "unaided", "from memory", "I recall" appear in arm A answer text; zero in B, B+
or D. Found by independent review, not by the harness.

Structural blinding holds (packets carry no arm labels, one key set across all 240 sheets,
all 24 orderings used), but an attentive grader could recognize the unaided arm from content.
**Cannot touch the D-versus-B null**; it cuts against **B over A**, the one comparison
reported as robust, in the direction of inflating it.

**Fix, for any future run:** either instruct the unaided arm not to narrate its own condition,
or strip first-person epistemic phrasing at pack time. The latter is safer (an instruction
can be ignored) but risks mangling substantive text; prefer a WARN in `tier3-pack.mjs` that
reports self-identifying sheets rather than silently editing answers.

**Check:**
```
node -e "...scan packets-v2 for /\b(unaided|from memory|I recall)\b/i, group by arm via blinding map"
```
At snapshot: `{"a":10}`.
