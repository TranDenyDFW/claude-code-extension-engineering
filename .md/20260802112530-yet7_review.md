## What the spec missed

1. The check-14 root cause above is a defect the spec did not ask anyone to find, only
   to report the run status. It is the repo's own defect class: a gate that is green on
   the author's machine and red everywhere else, caused by config invisible to the
   author (a global gitignore). The committed artifact does not reproduce the committed
   claim on a clean machine.
2. The agnix bad-matcher-regex fake catch (check 5a) is a live instance of a FOURTH echo
   channel the three hardening rounds did not close: config content echoed inside a
   genuinely file-anchored diagnostic. The scorer credits any file-anchored diag whose
   text matches the signal, at any level. A cheap hardening: score catch credit only
   from error-level structured diags, or strip bracketed config echoes (e.g.
   `[matcher=...]`) from diag text before matching; add a must-fail case pinning it.
3. The published summary column "Wrote during a run" (including the "claude plugin
   validate ... yes" cell) is not produced by renderMatrix and is not covered by any
   self-test; it exists only as prose in the doc. I did not re-verify it and nothing in
   the gates would catch it drifting.
4. tools/tier3-strip.mjs contains two literal NUL bytes (an intentional `' \x00 '`
   joiner). Harmless at runtime, but every text-mode tool (grep -I, some diff drivers)
   silently skips the file, which quietly exempts it from text-based sweeps like the
   spec's own dash scan. Worth a comment or an escaped `'\u0000'` literal so the source
   file stays text.
5. Cosmetic: the doctor's "scopes found:" header lists only scopes with a settings.json
   present, while skills/agents at an unlisted scope are still scanned and flagged (my
   fxB reported "scopes found: user" yet flagged a project-scope skill). Could mislead a
   reader into thinking a scope was not examined.
6. run-bench.mjs emits Node DEP0190 (args passed to a shell:true child process) on
   v24.14.1. Deprecations of this class have historically become throws; the bench
   runner will eventually need the spawn call reworked.
7. The doctor's process exit code reflects only BROKEN findings; settings-shadowing
   alone (INFO) exits 0. Reasonable design, but a CI consumer expecting non-zero on any
   finding would be surprised; it is not documented in the README section.
