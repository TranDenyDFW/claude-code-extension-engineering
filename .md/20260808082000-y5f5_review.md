### Check 21, judgement

**These commits address the pattern rather than adding another instance of it, and I can say why in
terms of what each step attacks rather than what it adds.**

The 72% signal means the defects were not in the code being fixed, they were in the *shape of the
response*: each fix moved an untested decision to the nearest place nothing was looking, and the only
instrument that ever caught it was the next human. A seventh instance fix would have been another
assertion at whatever boundary the author happened to be holding.

- Step 1 is not a check at all. It is the observation that four of this repository's strongest
  existing gates, about 110 authored assertion rows, were never invoked by any workflow. Finding that
  the instrument was switched off is a different kind of act from writing another instrument, and I
  verified it independently: `git show bdd9a3e:.github/workflows/freshness.yml` names only
  `scaffold-parity --check`, so five of the six invocations really had never run.
- Step 2 attacks a class no source-level fix can reach. Three of the historical defects were
  fabricated *data* behind correct code, and `proveArtifactGate` is the generalisation of that,
  carrying three properties most of this repo's earlier proofs lacked: baseline refusal, no-op
  detection, and the WRONG GATE rule that scores a mutant killed by the wrong rule as survived. The
  strongest evidence that it is doing real work is that wiring it produced a finding the author had
  no incentive to disclose, and I confirmed that finding historically with `git show 7a1f4b4~1` and
  behaviourally by running the pre-fix tool against three single-field mutations, all of which it
  passed at exit 0.
- Step 3 pins the one boundary a relocation cannot escape. Five rounds were lost to fixes verified at
  a function boundary while the process boundary moved; asserting the spawned CLI's exit code and
  stdout means the internals can be rewritten freely and the user-visible verdict still has to hold.
  Widening it from 1 executable to 6 is the difference between a contract and an anecdote, and check
  19 shows it catches a real tool mutation that the tool's own run does not.

The clearest single demonstration is check 15: with the ledger's text-drift check neutered, the tool
itself exits 0, the artifact proof exits 1, and the CLI contract exits 1. Three instruments, and the
tool's own opinion of itself is the weakest of them. That is a structural answer to "who watches the
fix", not another watcher of the same kind.

**The class of defect they still cannot reach: a defect in the shared assertion vocabulary itself.**
`tools/artifact-mutation.mjs` is now a single point of trust for two proofs and any future ones. Its
only guard is a self-test written by the same hand in the same commit, and it is verified by nothing
independent. If `got.includes(m.expect)` were subtly wrong (it accepts a mutant that trips its named
rule *plus* several others, which is how the duplicated-id mutant behaves), both consumers would
report green together and every gate downstream would inherit the same blind spot. This is not
hypothetical: the repo already contains two near-copies of that logic, `proveArtifactGate` and
`capability-catalog`'s `proveFail`, and they have already diverged in exactly the way that matters,
which is issue 1 above. Mechanically the missing piece is a second, differently-shaped instrument on
the prover itself, or a rule that there is one implementation and the old copy is deleted rather than
left beside the new one. The 72% pattern's last hiding place in this design is "the generalisation
was written and the specific case it generalised was left running".

The secondary class, cheaper to close, is prose. Issues 2 and 3 are both claims in commit messages
and published documents that no gate can read: `--check` asserted as wired when it is not, and a set
of self-describing counts that the numbers gate has no fact for. Every mechanical claim in these
commits that I could test held; the ones that failed were the ones only a human reads.
