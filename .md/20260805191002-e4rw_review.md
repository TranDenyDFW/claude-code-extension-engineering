## Issues found

1. **The credential fix was applied to the verification query but NOT to the harvest itself, so the
   tool's primary documented usage is still broken on this machine.** `ghEnv()` is passed only at
   `tools/gh-corpus-harvest.mjs:93` inside `searchTotal`. The actual harvest at lines 115-117
   spawns `gh api --paginate repos/anthropics/claude-code/issues?...` with `{ stdio: [...],
   windowsHide: true }` and no `env` option at all, so it inherits the expired `GITHUB_TOKEN`.
   Verified live: `gh api "repos/anthropics/claude-code/issues?state=all&per_page=1"` with the
   ambient environment returns `{"message": "Bad credentials", "status": "401"}` and exit 1, while
   the identical query with the variable unset succeeds. So `node tools/gh-corpus-harvest.mjs` with
   no flags, which the file header documents at line 25 as "harvest, then verify", cannot complete
   on this host. Mitigating: it fails LOUDLY, not silently. `main()` at line 289 checks `r.code !==
   0` and returns 1 with `harvest FAILED, not verifying a partial corpus`, so this cannot manufacture
   a false PASS. It is a functional gap and a correctness gap in the retraction, not a new instance
   of the reported-success-on-partial-data defect. Check 8 does not catch it because it only asks
   whether `searchTotal` gets the stripped env.

2. **`data/gh/README.md` line 52-53 publishes a claim that is not true, in the paragraph written to
   correct claims that were not true.** It states the tool now strips the tokens "the way
   `gh-staff-harvest.mjs` and `sources/collect.mjs` already did". Verified: `tools/gh-staff-harvest.mjs`
   contains no occurrence of `GITHUB_TOKEN`, `GH_TOKEN`, `process.env` or an `env` option anywhere;
   its only `gh` invocation is `execFile('gh', args, { maxBuffer: 96 * 1024 * 1024 }, ...)` at line
   109. A repo-wide `grep -rln "delete.*GITHUB_TOKEN" --include=*.mjs --include=*.js` returns
   exactly one file, `./tools/gh-corpus-harvest.mjs`. Separately, `sources/collect.mjs` does not
   exist in this repository at all (`find . -name collect.mjs` outside node_modules returns
   nothing); the file with that name lives in the sibling repo
   `P:\ClaudeExt\CCX-Extension-Research\sources\collect.mjs`, and that one DOES strip both
   variables at its lines 329-330. So of the two cited precedents, one is wrong and one is not in
   this repo. The same wording appears in the code comment at `tools/gh-corpus-harvest.mjs:70-71`.
   No check in the spec covers this sentence.

3. **The self-test's failure diagnostic for its final row prints a field that does not exist.** At
