## Checks

1. `node tools/extension-scaffold.mjs --self-test`
   - PASS if: exit code 0 AND final line is `SELF-TEST PASS`
   - FAIL if: non-zero exit, or any line begins with `  FAIL`

2. Scaffold a requirement with BOTH guarantee language and a fail-closed clause:
   ```
   node tools/extension-scaffold.mjs --requirement "Prevent any change to a file under `audit/`. The protection must still hold if the guard script is deleted or crashes." --out tmp/v/hard --name audit-guard
   ```
   - PASS if: exit code 0 AND output contains `mechanism          : permission-deny`
     AND contains `7 case(s): 7 passed, 0 failed.` AND ends with
     `DONE: the generated bundle satisfies its own conformance spec.`
   - FAIL if: any of those is absent, or the exit code is non-zero

3. Confirm the emitted deny rule uses the correct tool name. Inspect
   `tmp/v/hard/settings.json`
   - PASS if: the deny array contains a rule beginning `Edit(` and does NOT contain any rule
     beginning `Write(`
   - FAIL if: a `Write(` path rule is emitted. Per the official permissions page a `Write`
     path rule is accepted but never consulted, so emitting one would produce a bundle that
     protects nothing.

4. Scaffold a requirement with guarantee language but NO fail-closed clause:
   ```
   node tools/extension-scaffold.mjs --requirement "Block writes to `generated/` so nobody edits generated code by hand." --out tmp/v/soft --name gen-guard
   ```
   - PASS if: exit 0 AND output contains `mechanism          : hook` AND contains
     `5 case(s): 5 passed, 0 failed.`
   - FAIL if: it emits 7 cases (fail-posture cases here would make a correct hook fail its own
     spec, since a command hook fails open by design), or a non-zero exit

5. Confirm the soft bundle emitted NO fail-posture cases:
   ```
   node -e "const c=require('./tmp/v/soft/conformance.json');console.log(c.cases.filter(x=>x.kind==='fail-posture').length)"
   ```
   - PASS if: prints `0`
   - FAIL if: any other number

6. Out-of-family requirement must be REFUSED:
   ```
   node tools/extension-scaffold.mjs --requirement "Summarise the session into a changelog entry whenever work finishes." --out tmp/v/nope --name x
   ```
   - PASS if: exit code **2** AND output contains `UNSUPPORTED:`
   - FAIL if: exit 0, or a bundle is produced

7. The GENERATED specs must be falsifiable:
   ```
   node tools/extension-prove.mjs --prove-fail --bundles tmp/v
   ```
   - PASS if: exit 0 AND output contains `PASS: every enforce/wiring case goes red`
   - FAIL if: `PROVER IS HOLLOW`, or a non-zero exit

8. A sabotaged generated guard must FAIL its own spec. Back up outside the bundle, sabotage,
   observe, restore:
   ```
   cp tmp/v/soft/guard.mjs /tmp/guard.keep
   node -e "const fs=require('fs');const p='tmp/v/soft/guard.mjs';fs.writeFileSync(p,fs.readFileSync(p,'utf8').replace('p.startsWith','false && p.startsWith'))"
   node tools/extension-prove.mjs --bundle tmp/v/soft
   cp /tmp/guard.keep tmp/v/soft/guard.mjs
   node tools/extension-prove.mjs --bundle tmp/v/soft
   ```
   - PASS if: the sabotaged run exits **non-zero** with at least one `FAIL` line, AND the run
     after restore exits 0
   - FAIL if: the sabotaged run exits 0, which would mean the generated spec cannot fail

9. CRLF portability of the drift gate. Back up OUTSIDE the fixtures tree, because `--check`
   regenerates that directory:
   ```
   cp tests/prove-bench/fixtures/correct-guard/settings.json /tmp/s.keep
   node -e "const fs=require('fs');const p='tests/prove-bench/fixtures/correct-guard/settings.json';fs.writeFileSync(p,fs.readFileSync(p,'utf8').replace(/\n/g,'\r\n'))"
   node tests/prove-bench/make-fixtures.mjs --check
   ```
   - PASS if: exit code **0**. A byte hash would fail here, and would make CI green on Linux
     while every fresh Windows clone went red.
   - FAIL if: non-zero exit
   (the file is restored by `--check` itself, which regenerates the tree; confirm with a final
   `node tests/prove-bench/make-fixtures.mjs --check` exiting 0)

10. The same gate must still catch REAL content drift:

    node tests/prove-bench/make-fixtures.mjs --check
    node tests/prove-bench/make-fixtures.mjs --check
