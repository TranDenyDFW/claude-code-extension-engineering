# Capability catalog

`catalog.json` is the generated, version-stamped list of Claude Code built-in **tool
names** and **hook-event names**, with a citation behind every single one. It is the
input that makes `tools/extension-doctor.mjs` version-aware instead of opinionated.

Generated by `tools/capability-catalog.mjs`. Do not hand-edit it: every edit invalidates
the `integrity` seal, and the gates will say so.

| | |
|---|---|
| catalog version | `2.1.239` (read from `evidence/VERIFIED_VERSION`) |
| tools | 52 total: 44 current, 5 legacy, 2 historical, 1 unlisted |
| hook events | 31 total, all current |
| sources | 9 (2 primary, 5 supporting, 1 absence scan, 1 corroborating) |
| provenance rows | 103 |

## Why it exists

`extension-doctor.mjs` shipped two hand-typed Sets: `HOOK_EVENTS` (30 names) and
`KNOWN_TOOLS` (36 names). Measured against the docs mirror it was missing **14 real
tools** and **1 real hook event**, while carrying **7 names the current tools table does
not list**.

The consequence was not theoretical. `tools: PowerShell` in a subagent was reported
BROKEN by a tool whose published headline is 12 of 12 with **zero** false positives.
`PowerShell` has been documented since v2.1.84.

A hand-typed Set has no provenance, no version, and no way to notice it went stale. This
directory replaces it with an artifact where every name carries a line citation, the body
is sealed with a sha256, and three separate gates can prove it still matches reality.

Wiring the catalog in is a strict superset of the old Sets: **no name the doctor already
accepted is lost.** 15 tool names and 1 event name are gained; 7 names the doctor treated
as fully valid are now correctly qualified as legacy, historical, or unlisted.

## Commands

```
node tools/capability-catalog.mjs                      same as --check-integrity
node tools/capability-catalog.mjs --check-integrity    verify the committed catalog, NO MIRROR NEEDED (this is what CI runs)
node tools/capability-catalog.mjs --check              drift vs the docs mirror
node tools/capability-catalog.mjs --from-mirror <dir>  regenerate this file
node tools/capability-catalog.mjs --self-test          71 assertions, including must-fail cases
node tools/capability-catalog.mjs --prove-fail         10 mutants, each must be rejected by a NAMED gate
```

Exit codes: `0` pass, `1` fail, `2` cannot check (no mirror, or no catalog on this machine).

`--check` builds a fresh catalog into a `mkdtempSync` temp directory and compares. It
**never** writes `catalog.json`. A drift gate that repairs the drift it detects can only
fail once, so regeneration is a separate, explicit flag. The self-test asserts the
committed file is byte-identical before and after a drift check.

## Status taxonomy

| status | meaning | count |
|---|---|---|
| `current` | listed in the canonical tools table of `tools-reference.md`, or as a `###` heading under `## Hook events` in `hooks.md` | 43 tools, 31 events |
| `legacy` | the docs explicitly call it a previous name or a legacy tool that **is still accepted** | 5 tools |
| `historical` | announced in `changelog.md`, no coverage in any current reference page | 2 tools |
| `sdk-only` | documented only in the Agent SDK reference, with no alias or legacy statement | 0 (defined, currently unused) |
| `unlisted` | zero occurrences anywhere in the mirror | 1 tool |

**Precedence rule.** When a name is both alias-documented and documented only in SDK
pages, `status` records the runtime claim (`legacy`, meaning it still works) and the
optional `scope: "agent-sdk"` field records where that claim lives. Status answers "will
this work?", which is what a linter needs; scope answers "where is it written down?".
This is why `sdk-only` has no members today: every SDK-page-only name in the mirror also
carries an explicit "still accepted as an alias" statement, which is a stronger claim.

`unlisted` exists so a user with an unrecognised name in a subagent gets **told**, not
alarmed. Silently dropping such a name would resurrect the false-positive class this
whole exercise exists to kill.

Three classifications came out differently from the working assumption, and the doc lines
are the reason:

* **`Task` is not absent from the mirror.** It is an explicitly documented alias for
  `Agent` in three places. Reporting it as unknown would be a false positive.
* **`LS` is not absent either.** `changelog.md:5172` records the `LSTool` to `LS` rename,
  which makes it historical rather than unlisted. `mcp.md:1011` mentions it a second time
  ("The server provides access to Claude's tools like View, Edit, LS, etc.") but that
  sentence is stale prose in a tip about `claude mcp serve`: it still uses `View`, which
  the same changelog line renamed to `Read`. Stale prose is not an authoritative listing,
  so it is not used as evidence, and `LS` stays historical on the strength of the
  changelog alone.
* **`BashOutput` and `KillShell` do appear only in Agent SDK pages**, but those pages
  state they are previous names that still work. That is a runtime claim, so they are
  `legacy` with `scope: "agent-sdk"`, not `sdk-only`.

`KillBash` is a fourth alias in the same sentence as `KillShell`. It was in neither the
doctor's list nor agnix's, and it is generated here rather than hand-typed, so it came
along for free.

### One name deliberately NOT auto-derived

`agent-sdk__typescript.md` lines 2905 to 2951 define a `ToolOutputSchemas` union that
includes `ReadMcpResourceDirOutput`, `RefreshMcpToolsOutput`, `REPLOutput`,
`ProjectsOutput` and `ShowOnboardingRolePickerOutput`, none of which have a row in the
tools table. Stripping "Output" off a type name to invent a tool name is exactly the kind
of naive extraction this parser was built to avoid, so the catalog does not do it. Worth
a look the next time the tools table is revised.

## The parsing trap

A naive "every table row whose first cell is backticked" scan over `tools-reference.md`
returns **46** rows, not 43. It absorbs:

* `WebSearch` a second time, from the permission-rule table at line 87 under
  `## Configure tools with permission rules and hooks`
* `url` and `protocols`, from the WebSocket field table at lines 296 and 297 under
  `## Monitor tool`

The parser is therefore **section-scoped**: the canonical table is the one in the
preamble (before the first `##`) whose header is `Tool | Description | Permission
required`. `hooks.md` gets the same discipline: only `###` headings inside
`## Hook events`, fence-aware, stopping at the next `##`.

The self-test proves both halves of this. It runs the naive scanner and asserts it
**does** swallow `url` and `protocols`, then runs the real parser and asserts it does
not. A trap you cannot demonstrate is a trap you have not fixed. Against the live mirror
the same pair of assertions reads: naive 46, section-scoped 43.

## Cross-check: agnix 0.45.0

`tests/lint-bench/results.json` line 859 captures agnix 0.45.0 refusing an unknown tool
name and enumerating its own list of 47 in the error message. Recorded in the
`crossCheck` block:

* it agrees with the docs on **all 43** current tools, including **all 14** this project
  was missing;
* `docsCurrentItLacks` is **empty**: there is no documented tool agnix does not know;
* it additionally asserts `MultiTool`, `StatusBarMessageTool` and `TodoRead`, which have
  **zero** occurrences anywhere in the mirror;
* and `Task`, which the docs do cover, as a legacy alias.

**A benchmarked competitor's error message was more current than our own hardcoded
list.** That is the fact worth carrying out of this exercise.

It is **corroborating, never the arbiter**. The three names agnix asserts that the docs
do not support are recorded in `assertsUnsupportedByDocs` and are deliberately **not**
added to `tools`. Adopting them would mean letting a competitor define truth, which is a
worse failure than the one being fixed.

But the block is not decorative either. Because `results.json` is a committed file the
catalog does not own, it is the only **external** anchor available to the mirror-free
gate. See the next section.

## What each gate can and cannot catch

This matters, because CI runs the mirror-free gate.

| forgery | caught by | needs the mirror? |
|---|---|---|
| any hand edit, one byte anywhere | `INTEGRITY_MISMATCH` | no |
| a name dropped, counts left alone | `COUNTS_MISMATCH` | no |
| a name dropped **and** counts corrected **and** resealed | `CROSSCHECK_MISMATCH` | no |
| the above **and** the cross-check rewritten | `DRIFT_TOOL_MISSING` | **yes** |
| a hook event dropped, counts corrected, resealed | `DRIFT_EVENT_MISSING` | **yes** |
| a blanked or undeclared citation | `PROVENANCE_EMPTY`, `PROVENANCE_UNDECLARED_SOURCE` | no |
| a stale `catalogVersion` | `CATALOG_VERSION_MISMATCH` | no |
| the docs themselves changing | `DRIFT_SOURCE_HASH` | **yes** |

The honest boundary: **internal consistency can always be satisfied by a consistent
forgery.** Recompute the counts, reseal the hash, and nothing inside the file contradicts
anything else inside the file. Every mirror-free rule that survives such a forgery does so
because it reaches for something outside the file: `evidence/VERIFIED_VERSION` for the
version, and `tests/lint-bench/results.json` for the cross-check. Anything beyond that
requires the docs mirror, which is what `--check` is for. Run `--check-integrity`
everywhere; run `--check` wherever the mirror exists.

`--prove-fail` mutates the committed catalog ten ways in a temp directory and asserts each
one is rejected **by the gate named for it**. Nine of the ten are **resealed** first
(their integrity hash recomputed), because otherwise all ten would trip the same single
hash check and the other nine rules would be decoration that never actually runs. A
mutant caught by the wrong rule counts as a failure, not a pass. If any mutant survives it
prints `CATALOG GATE IS HOLLOW` and exits 1, which has been observed by neutering two
rules in a throwaway copy: 4 of 10 mutants went to `WRONG GATE` and the run exited 1.

## Schema

```
schemaVersion       integer, bumped when consumers must change
catalogVersion      the build this catalog describes, read from evidence/VERIFIED_VERSION
generated           ISO timestamp
generator           the exact command that produced the file
quotePolicy         how citation quotes were normalised (see below)
statuses            the taxonomy, so a consumer can validate without importing the module
sources[]           { id, role, sha256, bytes, note? }  every provenance.source MUST be an id here
counts              totals and per-status breakdowns, recomputed and compared on every verify
versionAwareness    { catalogVersion, newestChangelogVersion, catalogVersionIsNewestDocumented,
                      namesNewerThanCatalogVersion[] }
crossCheck          the agnix comparison, or null
tools{}             name -> { status, provenance[], since?, aliasOf?, scope?, reason? }
hookEvents{}        name -> { status, provenance[], since? }
integrity           sha256 over the canonicalised body with this field removed
```

`provenance[]` entries are `{ source, line, quote }`. `line` is 1-based and points into
the file whose sha256 is recorded in `sources[]`; `line: 0` means the citation is an
assertion of **absence** rather than a location. Every `quote` is longer than 10
characters, which is the citation floor `extension-doctor.mjs` findings must meet.

Canonicalisation for the hash: object keys sorted recursively, arrays left in order, no
whitespace. Reformatting the JSON therefore cannot change the seal, but reordering a list
can, which is intended.

**`quotePolicy`.** Quotes are markdown-link-flattened, whitespace-collapsed, truncated to
about 140 characters, and dash-family characters (U+2010 to U+2015, U+2212) are replaced
with " - " per the repo house rule. They are therefore **not byte-verbatim**. For exact
text, read the cited line from the source whose sha256 is in `sources[]`. Long paragraphs
are quoted in a window **around** the match rather than from the start of the line, so a
citation always visibly contains the evidence it is offered for.

**`since`.** The oldest `<Update label="...">` block in `changelog.md` whose bullet
announces the name as the direct object of "Added" ("Added `X`", "Added the X tool").
Deliberately conservative: 6 of 51 tools and 13 of 31 events have one. An absent `since`
means "never announced in that shape". It does **not** mean new, and it does **not** mean
old. Do not infer availability from its absence.

`versionAwareness.namesNewerThanCatalogVersion` is currently **empty**: nothing documented
here arrived after v2.1.220. `catalogVersionIsNewestDocumented` is `false` because the
changelog already documents v2.1.221, which matches `evidence/status.json` reporting the
verification as stale.

## Consuming it from extension-doctor.mjs

```js
import {
  loadCatalog, currentNames, knownNames, statusOf, citation, cmpVersion,
} from './capability-catalog.mjs';

const cat = loadCatalog();              // throws on a catalog that fails verification
const ok  = currentNames('tools', cat); // Set of the 43

if (!ok.has(name) && !name.startsWith('mcp__')) {
  const status = statusOf('tools', name, cat);   // null if genuinely unknown
  // status tells you WHICH message to write: legacy -> "still accepted, prefer <aliasOf>",
  // historical -> "no longer in the tools reference", unlisted -> "not in the docs at all".
  // citation() returns a ready-made string already over the 10 char floor.
}
```

Two things to be careful with:

* `verifyCatalogIntegrity(cat)` returns an **object** `{ ok, errors }`, which is always
  truthy. Test `.ok`. `loadCatalog()` already calls it and throws, so most callers do not
  need it directly.
* `cmpVersion` is numeric on purpose. `cmpVersion('2.1.9', '2.1.220') < 0`, whereas the
  string comparison `'2.1.9' < '2.1.220'` is **false** and gets the order backwards. A
  backwards version compare is a false-positive generator, which is the bug class this
  whole directory exists to remove. It is a self-test row.

## Regenerating

```
node tools/capability-catalog.mjs --from-mirror P:\ClaudeExt\CCX-Extension-Research\sources\docs\md
```

Regenerate when `--check` reports drift, or when `evidence/VERIFIED_VERSION` moves. The
generator refuses to write a catalog that does not verify, and it throws rather than
guessing if a page it depends on changed shape: a curated rule whose evidence has moved,
a `unlisted` name that has started appearing, or a tools-table row it cannot parse all
stop the build instead of quietly emitting a stale citation.
